# Security policy

Security fixes are applied to the latest release and the `main` branch.

Use GitHub's private vulnerability-reporting feature for issues that could expose credentials, private studio state, authorization records, user data, or unsafe execution paths. Do not post sensitive details, charters, evidence packets, or local paths in a public Issue.

For non-sensitive bugs, documentation problems, or installation questions, use the repository's Issue templates.

This Skill is a governance workflow, not a security boundary. Host permissions, workspace isolation, access control, qualified review, and human authorization remain authoritative.
